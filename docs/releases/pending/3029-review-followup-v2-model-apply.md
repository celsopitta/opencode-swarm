# v2 model-apply follow-up: sticky-error narrowing, normalized fallback model, registration lifecycle (PR #3029 review)

## What changed

- **The v2 model apply now uses the normalized fallback chain's model.** `advancePendingTaskModelRoute` returns the `modelString` of the entry the fallback actually advanced to. `fallbackIndex` counts positions in the **normalized** chain (`normalizeModelChain` output — deduped, parse-filtered), so indexing the raw `fallback_models` list by it could apply the failing primary or an unparseable entry when a fallback duplicates the primary or fails to parse. The `session.error` advance arms in `src/index.ts` now pass that field to `applyV2AgentModelOverride` instead of computing from the raw list.
- **The host-global v2 apply is narrowed to sticky-appropriate errors.** The applied model persists on the registered agent until restart, so both advance arms now apply it only when the error is `model unavailable` or a quota error — the classes where permanently rerouting the agent to the next chain entry matches the v1 sticky fallback semantics. Transient network-class failures advance the per-session fallback selection (unchanged) but no longer rewrite the agent's registered model.
- **Repeated applies no longer accumulate live registrations.** `applyV2AgentModelOverride` holds the `Registration` returned by each `ctx.agent.transform` in a map keyed by the exact registered agent name and disposes only the SAME agent's previous registration when a new apply succeeds; `clearV2AgentTransformSurface` (v2 cleanup) disposes all of them. Keying matters because the host's `Registration.dispose()` is the undo path for that transform's rewrite — disposing a *different* agent's registration would revert that agent's sticky model rewrite and reintroduce the #3022 unavailable-model failure for it. The map is FIFO-bounded (128 entries) so pathological agent-name churn cannot grow it without limit.
- **Sticky gate as a tested predicate.** The sticky-appropriate error classes (model unavailable, quota) are centralized in `isStickyModelError` (`src/utils/provider-error-classification.ts`), used by both v2 advance arms and pinned by classification-matrix rows; the arms' use of the gate and of the normalized-chain `modelString` is pinned at their `src/index.ts` call sites.
- **Regression coverage.** `tests/unit/host/v2/review-followup-3029.test.ts` pins the normalized-modelString advance (duplicate-of-primary + unparseable fallbacks in the raw list), the registration dispose lifecycle, the pump's identity-seeding call site, and the guardrails advisory negative control; `tests/unit/failures/classification-matrix.test.ts` pins `Model unavailable` classifying to `provider.unavailable` / `retry_fallback`.
